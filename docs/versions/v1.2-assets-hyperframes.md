# v1.2 Assets and HyperFrames

v1.2 的目标是提升视频的真实素材感。ToolReel 不能只靠卡片和文字讲工具，必须让用户看到官网、产品页面、demo、录屏或可信外部素材。

## 核心目标

- 素材采集从静态首页截图升级为多类型素材候选。
- HyperFrames 承担官网和网页现场展示，不只做占位视频。
- Creative 的分镜意图能决定要采集和展示哪些素材。
- 缺素材时允许跳过对应镜头，但不生成误导性画面。

## 必须实现

1. 自动素材采集增强：
   - 官网首屏截图。
   - 官网滚动截图或滚动录屏。
   - 产品功能页截图。
   - docs、blog、changelog、use case 页面候选。
   - 官方 demo 视频链接候选。
   - 官方社媒链接候选。
   - 第三方视频或文章候选，必须标记来源和可信度。
2. 支持人工补充素材：
   - `assets.manual.json`
   - 本地录屏。
   - 官方视频文件。
   - 第三方视频链接。
   - 推特/X 评价截图或链接。
3. HyperFrames 官网场景：
   - `WEBSITE_DEMO`
   - `LANDING_PAGE_DEMO`
   - `PRODUCT_PAGE_SCROLL`
4. HyperFrames 画面能力：
   - 竖屏适配。
   - 页面滚动。
   - 区域放大。
   - 重点区域高亮。
   - 遮罩弱化背景。
5. 稳定性检查：
   - 页面加载超时检测。
   - 黑屏检测。
   - 空白页检测。
   - cookie 弹窗和遮挡检查。
   - 失败时跳过 HyperFrames scene，不生成保底假画面。

## HyperFrames 职责边界

HyperFrames 负责网页和产品现场感：

- 官网展示。
- 网页滚动。
- Landing Page 展示。
- 产品页面高亮。
- demo 区域扫过。
- docs 或案例页面证据展示。

HyperFrames 不负责：

- 结构化卖点卡片。
- 封面。
- CTA 总结页。
- 榜单和对比主视觉。
- 全片字幕系统。

这些仍由 Remotion 和字幕模块负责。

## 不做

- 不强依赖某个平台的登录态。
- 不爬取需要绕过权限或付费墙的内容。
- 不下载和重剪版权不明确的视频文件。
- 不把第三方评价改写成未验证背书。

## 验收标准

运行 CLI 后应满足：

- `assets.json` 包含多类型素材候选。
- 至少 1 个网页展示类 scene 使用 HyperFrames 真实渲染。
- HyperFrames 输出不是黑屏、白屏或纯静态占位。
- `run.json` 能记录 HyperFrames 成功或跳过原因。
- 缺素材时画面不出现 `unknown`、`真实官网截图` 等误导性文案。

## 当前实现

- `assets.json` 输出 `pageCandidates`、`imageCandidates`、`videoCandidates`、`socialCandidates`、`externalCandidates`、`localRecordings` 和 `selectedAssets`。
- `assets.manual.json` 支持补充 logo、图片、视频、社媒、页面、外部候选、引用和本地录屏。
- 官网链出的社媒、视频和外部页面会作为 `externalCandidates`，只作为素材候选，不改写成未验证背书。
- `WEBSITE_DEMO`、`LANDING_PAGE_DEMO`、`PRODUCT_PAGE_SCROLL` 默认交给 HyperFrames。
- HyperFrames scene 缺少可用网页截图或产品截图时会标记 `renderStatus: "skipped"`，并在 `run.json.warnings` 记录原因。
- 跳过 HyperFrames scene 后，TTS 只为实际渲染的 scene 生成口播，避免音画错位。
- HyperFrames scene 渲染后会做 scene 级 QA：黑屏、白屏/空白、纯静态检测；QA 失败时跳过该 scene，并重新生成剩余 scene 的 TTS/字幕。
- 采集 HTML 时会记录 cookie、consent、privacy banner 等遮挡风险到 `assets.notes`。
- 官网临时 403 或抓取失败时，会优先复用同工具历史成功的 `research.json` 和 homepage 截图，再进入低置信 fallback。

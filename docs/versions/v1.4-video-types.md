# v1.4 Video Types

v1.4 的目标是在单工具科普视频稳定后，扩展更多内容形态。这个阶段不追求一次支持所有格式，而是逐个视频类型形成稳定模板和验收标准。

## 核心目标

- 支持更多 `videoType`。
- 不同视频类型有不同 research、script、scene 和 renderer 策略。
- 仍保持 CLI 可运行，不依赖后台。

## 优先视频类型

| videoType | 说明 | 优先级 |
| --- | --- | --- |
| `product_pick` | 单个工具科普/推荐 | 已有，继续增强 |
| `tutorial` | 一个工具的简短教程 | 高 |
| `comparison` | 两个或多个工具对比 | 高 |
| `top_list` | 某个场景下的工具榜单 | 中 |
| `update_news` | 工具新功能或版本更新速递 | 中 |
| `website_demo` | 官网/产品页展示型视频 | 中 |

## 必须实现

1. 每个 videoType 都要有独立脚本策略：
   - `tutorial` 强调步骤。
   - `comparison` 强调差异和适用场景。
   - `top_list` 强调筛选标准。
   - `update_news` 强调更新内容和影响。
2. 每个 videoType 都要有 scene plan：
   - 不复用同一套固定 5 段结构。
   - Scene 数量仍建议 4-7 个。
3. 每个 videoType 都要有 renderer 默认策略：
   - 榜单和对比以 Remotion 为主。
   - 网站展示以 HyperFrames 为主。
   - 教程可以混合 Remotion 和 HyperFrames。
4. CLI 支持：

```bash
pnpm generate --name="Cursor" --url="https://cursor.com" --type="tutorial"
pnpm generate --name="Cursor" --url="https://cursor.com" --type="comparison"
pnpm generate --topic="AI coding tools" --type="top_list"
pnpm generate --name="Cursor" --url="https://cursor.com" --type="website_demo"
pnpm generate --name="Cursor" --url="https://cursor.com" --type="update_news"
```

## 不做

- 不在 v1.4 做自动发布。
- 不在 v1.4 做团队协作后台。
- 不生成无证据榜单排名。
- 不在缺少对比证据时强行输出优劣结论。

## 验收标准

- 至少 2 个新增 videoType 可以完整输出 `final.mp4`。
- 每个 videoType 的 `script.json` 结构明显不同。
- `run.json` 能记录 videoType、scene plan 和 renderer route。
- 不同视频类型不会共用同一套生硬模板文案。

## 当前实现

- `tutorial`：结构为上手入口、核心功能试用、放进工作流和判断是否值得深用。
- `comparison`：结构为官方定位、对比维度、适用场景和推荐判断，不生成无证据优劣排名。
- `top_list`：支持 `--topic`，在没有具体官网 URL 时走 topic-level planning，只讲筛选标准和试用顺序。
- `website_demo`：以 `LANDING_PAGE_DEMO` 和 `PRODUCT_PAGE_SCROLL` 为主，优先展示真实网页现场。
- `update_news`：以官方来源、更新重点和影响场景为主，不夸大成“颠覆式”结论。
- renderer 路由按 scene 类型决定：网页展示类走 HyperFrames，榜单、对比、推荐和总结类走 Remotion。
- 非 `product_pick` 类型的输出目录会追加 videoType 后缀，例如 `outputs/YYYY-MM-DD-cursor-tutorial/`，避免同一天同一工具的不同视频类型互相覆盖。
